## 2. 任务明细

### T01 数据结构与接口契约

**目标与依赖**：建立所有后续任务共同使用的数据模型及接口，无前置任务。

**模块**：`backend/internal/domain`、`store`、新增 `dashboard` 模块、管理路由及 `frontend/src/api/types.ts`。

**输入**：[设计方案第 3—8 节](dashboard-design.md#3-分组归属与售卖倍率)中的绑定、指标、事件、结算和查询契约。

**步骤**：

1. 增加分组可空售价、单值绑定 DTO、请求/尝试快照与来源类型；绑定继续使用原关联表，增加调用方唯一索引，避免同时引入两套关系来源。
2. 设计独立统计请求、尝试、事件凭据、分钟/日汇总、运行区间、设置模型，补时间和维度索引。财务事实保存十进制金额、计价版本、完整性及原因。
3. 分开请求级财务与尝试级消耗的聚合键；明确无分组维度、对象删除后的名称快照、查询使用的指标族。
4. 定义 `/dashboard/*` DTO、SSE 快照、通用质量元数据和设置校验，补齐前后端类型。
5. 实现可重复启动的增量迁移；若出现意外多组绑定，给出冲突 ID 并停止迁移，不自动删改关系。
6. 增加 `PlatformKey.probe_enabled` 非空默认 true、Key 创建/更新的可选布尔输入、列表/详情输出及结构化跳过结果；迁移已有 Key 为 true，重复迁移保护已保存的 false，明确省略与 false 的区别。

**输出**：迁移与模型、接口类型、契约样例、相关索引及兼容行为。

**验收与测试**：SQLite/PostgreSQL 新库与现有结构升级均成功；重复迁移不改历史数据；现有售价为空、单组与未绑定均保留；唯一索引拒绝并发多组关系；业务汇总不随诊断日志级联删除；DTO 对空值、零、字段省略有明确区分。

### T02 单分组约束与售卖倍率

**目标与依赖**：实现唯一请求归属和配置入口，依赖 T01。

**模块**：`handler/admin.go`、`handler/routegroup.go`、`ops/routegroup.go`、`handler/gateway.go`、`ApiKeysView.vue`、API 客户端。

**输入**：T01 绑定/售价契约；[设计方案第 3 节](dashboard-design.md#3-分组归属与售卖倍率)。

**步骤**：

1. 支持 `route_group_id`，兼容旧数组零个/一个元素；省略、清空、冲突分别处理，使用事务保存。
2. API 密钥分组选择改为可清空单选；分组新增售价输入与“未配置”状态，零售价清晰呈现为赠送。
3. 请求入口在读取正文前捕获分组、名称、售价及不可变目录版本；解析模型后从固定版本补齐模型价格，处理解析失败的终结记录；每次选中上游捕获成本倍率。
4. 保持未绑定密钥全局调度；已绑定只使用该组成员。关联改动不使进行中的请求改价，后续请求使用新关系。
5. 保持当前额度扣减和 `/v1/usage` 行为；分组有调用方绑定时拦截删除并列出冲突对象。

**输出**：配置 UI/API、绑定约束、请求快照及回归结果。

**验收与测试**：未绑定正常转发；单分组按现有策略选 Key；停用/不匹配组无全局回退；同 Key 多组共享仍按入口组定价；组内重试不改变售价；慢上传时改分组售价及目录价格，本次请求仍用入口版本；调价只影响新请求；新旧字段冲突返回 400；删除使用中分组有提示；额度扣减与原实现一致。

### T02A 上游 Key 独立探测开关

**目标与依赖**：允许 Key 保持启用且关闭诊断探测，依赖 T01；不改变正常业务调度资格。

**模块**：`PlatformKey`、`handler/admin.go`、`handler/dto.go`、`handler/consumer_ops.go`、`ops/ops.go`、诊断请求的网关上下文、`jobs`、`UpstreamsView.vue` 及前端 API 类型。

**输入**：T01 开关与诊断来源契约；[设计方案第 3.3 节](dashboard-design.md#33-上游-key-可启用但关闭探测)。

**步骤**：

1. 接通 Key 创建/更新/读取的 `probe_enabled`，通过存在性识别处理更新，确保 ORM 默认值不会吞掉显式 false；Key/提供商启停不重置此值。
2. 定时和手动批量探测在排队前过滤，在统一 `ProbeKey` 内、读取配置后且解密/上游调用前拦截；批量 worker 将关闭导致的跳过计入 skipped，覆盖单 Key 的两个管理入口。
3. 管理员测试 API 密钥沿原允许集合增加诊断候选限制，发出前复核开关；全部关闭返回跳过。限制仅作用于服务端标记的测试流量，不作用于真实请求及 `recovery_validation`。
4. 跳过不写探测样本、健康错误、最后探测时间和失败统计，也不消耗节流名额。关闭前已经获准发出的探测允许完成；关闭后排队任务重新校验。
5. 提供商页新增独立“允许探测”开关、状态标识、禁用探测操作的原因说明与批量跳过提示；关闭时保留探测间隔，余额/倍率/模型管理操作继续可用。
6. 重新开启后按原间隔和近期请求抑制规则调度，不补跑旧任务；补充回滚旧应用可能恢复探测的说明。

**输出**：独立开关 API、统一诊断控制、提供商页交互及模块测试。

**验收与测试**：旧数据默认开启；创建 false/更新 false/省略/非法 null/重启均符合契约；启用且停探的 Key 可服务正常请求，真实失败与恢复继续影响业务熔断；定时、全部、提供商、两种单 Key 入口的轻/深探测均无上游请求；管理员测试只选允许探测的候选；队列期间关闭计 skipped 不计 failed；无新 ProbeLog/last_probe_at/节流副作用；余额、倍率、模型操作可用；重新打开恢复频率；探测停用和 Key 停用在 UI 中清楚区分。

### T03 实时计数与 SSE

**目标与依赖**：完成四项实时指标服务，依赖 T01，可与 T02/T04 独立开发。

**模块**：新增 `dashboard` 运行态服务、网关生命周期、容量获取/释放挂点、管理 SSE handler/router。

**输入**：T01 实时类型；[设计方案第 4、5 节](dashboard-design.md#4-指标字典)。

**步骤**：

1. 为业务接入和尝试资源持有建立幂等生命周期令牌，覆盖返回、取消、异常释放；实现实际 HTTP 调用开始的独立尝试 RPM 挂点。
2. 实现滚动 60 秒窗口、250ms 过期淘汰和至多 250ms 推送合并；使用可注入时钟，避免测试依赖长时间等待。
3. 实现 SSE 首次完整快照、单订阅者最新值队列、心跳、写超时、断开清理、实例标识和重启窗口状态。
4. 接入现有管理员认证，核实服务端、Vite 代理和部署反代的 flush、超时、无缓冲行为。
5. 输出并发积分和峰值的分钟样本给 T04；运行态逻辑不等待数据库和日志。

**输出**：`/dashboard/live`、生命周期指标模块、SSE 示例、部署注意事项。

**验收与测试**：开始/结束各计一次、计数不为负；重试只增加上游 RPM；获取容量但本地构建失败只影响资源并发；无新流量时 RPM 过期下降；测试流量排除；多个页面不放大计数；慢订阅者不拖慢网关；首次连接即时快照、重启窗口不满提示、注销订阅释放资源。浏览器端到端 ≤1 秒在 T07 验收。

### T04 费用测算与持久汇总

**目标与依赖**：得到可解释、可恢复且不重复的经营统计，依赖 T01、T02；可先用 T01 定义的运行样本接口开发，T03 在集成时接入。

**模块**：新增 `dashboard` 结算/存储服务、`handler/gateway.go`、`handler/attempt.go`、费用解析、`jobs` 与统计清理逻辑。

**输入**：价格与来源快照、用量存在标记、请求及尝试终结事件；[设计方案第 6 节](dashboard-design.md#6-价格快照结算与持久统计)。

**步骤**：

1. 统一两种协议的非缓存/缓存 Token，保持原始用量证据；避免重复扣除缓存。报告费用与估算费用分字段保存。
2. 用快照价格和倍率计算收入、尝试成本；零价、失败、缺售价/用量分别处理，保存完整性原因。
3. 调整终结顺序，保证最后一个尝试完成后请求结算；以内部 UUID 幂等写入，分开请求财务和尝试消耗。
4. 事务更新分钟及日汇总，保留可合并延迟直方图、已知部分及完整集合金额；正确分摊提供商收入和重试成本。
5. 接入重试队列、恢复扫描、统计运行区间及缺口标记；6 分钟残留请求终结为不完整，不虚构费用。
6. 增加独立保留任务：30 天分钟/事实、长期日汇总、31 天去重凭据及超龄事件拒绝；保护未处理事件。接入 T03 并发样本。

**输出**：费用快照、幂等事件和汇总、恢复/清理任务、数据质量状态。

**验收与测试**：倍率及目录调价不改历史；缓存计价符合协议；失败尝试成本纳入、未知费用不填零；跨提供商失败后成功只产生一笔收入；重复事件及事务重试不重复加总；跨日请求归属符合字典；数据库错误、进程中断和队列溢出显示缺口；24 小时日志清理不删经营统计；长期累计不重复当天；旧日志不回算利润。

### T05 聚合查询与充值推荐

**目标与依赖**：提供仪表盘查询和解释性推荐，依赖 T04。

**模块**：`dashboard` 查询/推荐服务、管理 handler/router、持久设置。

**输入**：持久汇总、当前提供商余额、推荐设置；[设计方案第 7、8 节](dashboard-design.md#7-充值推荐)。

**步骤**：

1. 实现 overview/trends/rankings，严格使用各自指标族，避免把请求成本与尝试成本相加。
2. 实现区间、时区、粒度及分页校验，返回统计起点、缺口和完整性；长期区间使用日汇总。
3. 按提供商 ID 去重余额，区分全部、启用、未知、不限额、过期；余额刷新时间不伪装成查询时间。
4. 实现 24 小时消耗速度和充值紧急榜；缺口、零消耗、余额失效均按设计降级。
5. 实现近 7 天质量筛选、相同需求性价比比较、共有需求权重和覆盖门槛；提供商参与请求按 UUID 去重，共同权重按唯一成功业务请求基准费用计算，使用设计方案跨提供商重试示例验证；提供完整推荐原因与待观察项。
6. 实现设置读取/更新和输入校验。推荐固定使用当前 24 小时/7 天窗口，不继承页面历史筛选。

**输出**：四类聚合 API、推荐设置 API、查询与推荐测试。

**验收与测试**：同提供商多 Key 不重复余额；当前余额与历史金额分离；倍率低但质量差的不进入投资榜；样本少、零成本、财务覆盖不足不占据榜首；需求结构不同使用共同权重；交集覆盖不足仅给需求分榜；错误时间范围返回 400；查询不遍历请求正文或依赖已清理日志。

### T06 仪表盘前端

**目标与依赖**：完成可日常使用的首页，依赖 T02、T03、T05。

**模块**：新增 Dashboard view、SSE 客户端、API 类型/方法、router、AdminLayout、图表组件和日志筛选。

**输入**：实时和聚合接口；[设计方案第 8 节](dashboard-design.md#8-接口与页面)。

**步骤**：

1. 新增 `/dashboard` 和菜单，设为默认首页；使用 Naive UI，安装 ECharts 并按需导入。
2. 封装带 Bearer 的 fetch SSE 解析器；处理数据块边界、心跳、实例变化、过期、退避、401、暂停及退出销毁。
3. 实现四项实时卡片和短时曲线、当前余额及期间经营卡片；实时与历史数据各用自己的更新机制。
4. 增加日期筛选、趋势、经营排行、两个充值榜单和待观察区；显示统计覆盖、近似分位数、推荐依据及数据起点。
5. 添加提供商/分组定位、日志分组过滤与跳转；统计范围超过日志保留期时解释汇总和明细差异。
6. 处理空数据、接口失败、负毛利、长名称、大金额与移动端；保持原数据并标记过期，避免失败时显示虚假零值。

**输出**：仪表盘页面、流式客户端、图表、下钻和导航。

**验收与测试**：不下载全部日志做汇总；四项指标无 5 秒轮询；日期切换不改变当前实时卡片；连接状态可见，暂停恢复正确；离开页面无残留订阅；敏感 Token 不进入 URL；PC/移动端可读；图表 dispose；401 与现有登录流程一致。

### T07 集成验证与修复

**目标与依赖**：集中验证整条链路，依赖 T02—T06 和 T02A。开发期间无需反复执行全量验证。

**模块**：Go 单元/集成/race 测试、前端类型构建、浏览器回归、隔离测试数据库与代理环境。

**输入**：已接通的系统及前述任务模块测试；[设计方案验收边界](dashboard-design.md#9-兼容交付与验收)。

**步骤与测试矩阵**：

| 场景 | 核验结果 |
| --- | --- |
| 业务开始、结束、取消、读取失败、异常退出 | 生命周期计数正确，无负数或残留 |
| 同 Key 重试、换 Key、容量拒绝、本地准备失败 | 两种 RPM 和尝试并发按定义分别变化 |
| 停止流量超过 60 秒 | RPM 按滚动窗口衰减至零，无需新请求触发 |
| 首次订阅、断线、心跳超时、暂停、401、离开页面、重启 | 完整快照、过期状态、恢复和资源清理正确 |
| 250ms 合并及真实代理链路 | 受控正常前台环境每次被检查变化到 DOM 更新 ≤1 秒 |
| 多页面与慢客户端 | 计数不重复、网关不被推送阻塞；队列有界 |
| 一组多调用方、一个上游 Key 多组、未绑定密钥 | 售价归属准确、未绑定保持全局调度且不计算利润 |
| Key 启用但关闭探测，覆盖定时/批量/单 Key/管理员测试的轻深路径 | 诊断不访问上游，返回跳过且不写失败样本；正常业务仍可转发 |
| 排队期间关探测、已开始探测、重新开启、重启及迁移 | 排队复核，在途允许完成；开关持久保留，按原周期恢复，不补跑 |
| 关闭探测后余额/倍率/模型更新、真实业务失败及熔断恢复 | 管理同步可用，真实业务指标及恢复规则不被探测开关屏蔽 |
| 调价、缓存读写、零 usage、缺 usage、图片无价 | 快照稳定、零与未知区分、归一化无双扣 |
| A 提供商失败后 B 成功、全失败、负毛利 | 收入只计一次，费用分摊与完整集合守恒 |
| 重复结算、并发更新、SQL 失败、崩溃重启 | 已持久化事件可恢复且不重复；潜在丢失标缺口 |
| 跨上海零点、30 天清理、24 小时诊断清理 | 时间桶、累计、趋势、长期日数据正确 |
| 余额未知/不限/过期、质量差/样本少、不同需求结构 | 推荐降级合理，避免伪排名 |

执行后端 `go test ./...`、`go vet ./...`（工作目录 backend），对新增统计和相关 handler/picker/metrics 执行 race 检查；Windows 缺少 race 工具链时在支持的平台补齐并记录。分别验证 SQLite/PostgreSQL，Redis 相关测试使用隔离实例。前端执行 `npm ci`、`npm run build`（工作目录 frontend），再运行浏览器交互检查。

实时延迟测试以本机受控服务和浏览器统一时钟测量：记录服务端指标变化、快照序号与浏览器 DOM 更新时间；负载覆盖 10/100 个并发请求、1/10 个订阅者，报告最大值及分位数。允许合并期间的瞬时值不逐条展示，但展示快照的新鲜度必须满足 1 秒目标；并发峰值另由事件积分模块保存。测试不连接生产流量。

**输出**：命令结果、测试环境、场景通过/失败、延迟数据、浏览器截图和修复记录。必要时新增 `docs/dashboard-validation.md`，本次仅先规划该产物。

**完成条件**：必测项通过，失败项已修复复测；明确标记未运行项，不把跳过当通过；没有剩余影响金额正确性、计数释放或实时延迟的阻塞缺陷。

### T08 上线与运行检查

**目标与依赖**：让生产上线可验证、可回滚，依赖 T07。

**模块**：部署配置、数据库迁移、反代、运行观测及相关说明文档。

**输入**：T07 验证记录、构建产物、部署环境配置。

**步骤**：

1. 备份数据库，核对实际绑定没有多组；检查单实例部署和持久数据库卷。确认原日志保留周期不被本功能延长。
2. 部署增量迁移和应用，反代对 live 路径关闭缓冲、缓存与压缩聚合，空闲超时至少 60 秒。
3. 确认原密钥可用、未绑定密钥行为保留；已有分组显示未配置售价。录入售价只影响后续请求，不重写历史。
   检查旧上游 Key 默认允许探测；选择一把启用 Key 关闭探测，确认自动/手动诊断跳过且真实请求继续成功，重启后开关值保留。
4. 小流量检查四项指标、新请求收入/成本、失败重试费用、数据质量状态与浏览器连接；观测一个 60 秒完整窗口。
5. 核实累计不随重启回零，日志清理后统计仍可查。运行满 24 小时后核对充值紧急榜，近 7 天推荐在样本足够后自然出现，不手工补造样本。
6. 监控 SSE 活跃数、慢连接丢弃、结算失败/队列深度、统计缺口、聚合延迟和推荐覆盖率。
7. 如需回滚，先保存故障证据，恢复上一应用版本，保留新增数据表及绑定唯一索引；旧界面多选提交将受到唯一索引限制，单组及未绑定调用保持可用。标记旧版本运行时段无新仪表盘数据，回滚不执行索引删除；重新升级前检查唯一约束及绑定现状。
   旧应用忽略 `probe_enabled`，可能恢复对已关闭 Key 的诊断探测；回滚记录列出受影响 Key 并提示操作人员，重新升级不覆盖已保存的 false。

**输出**：部署检查记录、配置说明、统计起始时刻和回滚步骤。

**验收**：在线验证实时刷新、单组与未绑定回归、历史统计保留；无重复收入或余额双计；运营人员可以从页面判断估算范围、推荐依据和缺失数据。
